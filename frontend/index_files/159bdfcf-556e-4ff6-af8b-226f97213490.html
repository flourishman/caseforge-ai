CaseForge AI — Complete Deploy Guide (First Time, VSCode + GitHub)

0. What We're Building (How It All Connects)

You (Browser)   ↓[Landing Page]  -> Vercel (caseforge-ai.vercel.app) — Marketing site   ↓ Clicks "Launch App"[App / Frontend] -> Vercel (/app) — React UI with 6 modules   ↓ Calls API: POST /api/generate-test-cases   ↓ Needs API URL[Backend] -> Render.com (caseforge-api.onrender.com) — FastAPI   ↓ Calls[LLM] -> OpenAI API (gpt-4o-mini) — Real AI, or mock if no key   ↓ Returns JSONBackend formats -> Postman JSON, Jira Payload, Gherkin   ↓Frontend shows results + Export buttons

Landing and App are static (Next.js/React) — cheap to host on Vercel.
Backend is dynamic (Python) — needs server, host on Render.
LLM is external — you just add API key.

1. Prepare Your Folder Structure in VSCode

Open VSCode, open Terminal (Ctrl + `). Run:

mkdir caseforge-aicd caseforge-ai

Create this structure:

caseforge-ai/├── frontend/│   ├── landing/      <- Put landing page HTML here│   └── app/          <- Put real app HTML here├── backend/│   ├── main.py│   ├── services/│   ├── requirements.txt│   └── .env├── README.md└── .gitignore

In VSCode: File -> Open Folder -> Select caseforge-ai

Create .gitignore file (root):

node_modules/dist/.env__pycache__/*.pycvenv/.DS_Store

2. Add Your Files

Backend: Unzip caseforge-backend.zip you downloaded into backend/ folder.
Check: backend/main.py should exist.

Frontend:

  • Download landing page: Save as frontend/landing/index.html
  • Download app: Save as frontend/app/index.html

You now have 2 HTML files. For Vercel, we'll convert them to a simple Next.js or just deploy as static? Easiest for first time: Deploy as static sites.

Simpler for learning: Create one frontend folder with 2 pages:

frontend/
index.html (landing)
app.html (app)

Create frontend/.env.local (later for local dev):

NEXT_PUBLIC_API_URL=http://localhost:8000

Create backend/.env (copy from .env.example):

OPENAI_API_KEY=sk-proj-YOUR_KEY_HERE# Leave blank for now to use mock mode

3. Test Backend Locally (LLM Connection)

In VSCode terminal:

cd backendpython -m venv venv# Windows: venv\Scripts\activate# Mac/Linux: source venv/bin/activatepip install -r requirements.txtuvicorn main:app --reload --port 8000

Open http://localhost:8000/docs — You should see Swagger docs with 6 endpoints.

Test one: POST /api/generate-test-cases with:

{"requirement": "Users reset password via OTP valid 10 mins"}

If you have no OPENAI_API_KEY, it returns mock data with IDs CF_001... — That's intentional! Your app works without paying.

To use real AI: Get key from platform.openai.com -> API Keys -> Create -> Paste into backend/.env -> Restart uvicorn.

4. Test Frontend Locally (Frontend → Backend Connection)

Open NEW terminal in VSCode (Ctrl+Shift+`):

cd frontend# If you have Node: npx serve .# Or simple Python server:python -m http.server 3000

Open http://localhost:3000/app.html — In top bar API URL input, paste http://localhost:8000 and click Save.

Now click Generate in any module. Check browser DevTools (F12 -> Network tab) — You will see POST to localhost:8000/api/... That's frontend calling backend!

This is the key connection: Frontend (fetch) -> Backend (FastAPI) -> LLM (OpenAI).

6. Deploy Backend to Render (Connects LLM)

  1. Go to render.com -> Sign up with GitHub
  2. New + -> Web Service -> Connect caseforge-ai repo
  3. Settings:
    • Root Directory: backend
    • Runtime: Python 3
    • Build Command: pip install -r requirements.txt
    • Start Command: uvicorn main:app --host 0.0.0.0 --port $PORT
    • Plan: Free
  4. Advanced -> Add Environment Variable:
    • Key: OPENAI_API_KEY, Value: sk-proj-...
    • Leave empty for mock mode first
  5. Create Web Service -> Wait 2 mins -> You get URL: https://caseforge-ai-backend.onrender.com
  6. Test: Open https://your-url.onrender.com/docs — Should work!

7. Deploy Frontend to Vercel (Connects to Backend)

  1. vercel.com -> Sign up with GitHub
  2. Add New Project -> Import caseforge-ai
  3. Framework: Other (since we have static HTML for now)
    • For simplest: Deploy frontend folder as static
    • Better: If you want Next.js later, we can convert. For now:
    • Root Directory: frontend/landing (deploy landing first)
    • Build: none, Output: .
  4. Deploy -> You get https://caseforge-ai.vercel.app
  5. Now add App: Vercel -> Same repo -> New Project -> Root: frontend/app -> Name: caseforge-ai-app -> Deploy -> You get second URL.

Even better: Deploy as monorepo later with routes / and /app.

  1. Connect them: In your landing page HTML, change Launch App button href to your app URL.

  2. In your App, paste your Render backend URL into the top API URL field and Save — Now landing -> app -> backend -> LLM are all connected!

8. How Backend Structure Talks to Frontend (Code Review Lesson)

Open backend/main.py in VSCode:

@app.post("/api/generate-test-cases")async def generate_test_cases(data: RequirementInput):    result = await llm.generate_test_cases(...)    return result

This is an endpoint. Frontend calls it.

Open backend/services/llm_service.py:

SYSTEM = "You are CaseForge AI, Senior QA..."PROMPTS["test_cases"] = "Generate 10-12 test cases as JSON..."async def _call(self, prompt):    if self.use_mock: return self._mock(prompt)  # Works without key!    else: call OpenAI API

This is where AI magic happens. It tries real AI, falls back to mock.

Open frontend/app/index.html — Find callApi function:

const apiUrl = localStorage.getItem('caseforge_api_url')fetch(`${apiUrl}/api/generate-test-cases`, {method:'POST', body: JSON.stringify({requirement})})

This is frontend → backend connection. Data flows:

User types requirement in <textarea>
-> Click Generate calls callApi()
-> fetch() sends JSON to FastAPI
-> FastAPI calls LLMService._call()
-> LLM returns JSON (real or mock)
-> FastAPI returns JSON to frontend
-> Frontend renders cards/table

That's full-stack!

9. What To Learn Next (Deep Dive Checklist)

In VSCode, open each file and trace:

  • main.py: How Pydantic models validate input (RequirementInput)
  • llm_service.py: How prompts force JSON output (response_format json_object)
  • postman_generator.py: How it builds Postman Collection schema
  • app/index.html: How localStorage saves API URL, how fallback works
  • Network tab: Watch real request/response
  • Render logs: See backend logs when frontend calls

10. Common First-Time Errors

  • CORS error: Already fixed by CORSMiddleware in main.py (allow_origins=["*"])
  • Backend sleeps on Render free tier: First request after 15 mins takes 30s to wake — Normal
  • API URL not saving: Check localStorage in DevTools -> Application -> Local Storage
  • Git push fails: git config --global user.email "you@email.com" and user.name
